# Flow journal -- document-render-service (CR-3a)

First of three increments decomposing the retired `agreement-document-render` proposal. Ships the
render capability only: a Gotenberg-backed `DocumentRenderer`, one bundled rental-agreement
Thymeleaf template, offline/network-deny + escaping. No agreement wiring, no endpoint, no frontend.

## Decomposition (agreed structure)

CR-3 was split into three independently-shippable increments; the monolith was retired to
`archive/2026-07-11-superseded-agreement-document-render/` (unimplemented, decisions reused verbatim):
- **CR-3a `document-render-service`** (this) -- the renderer.
- **CR-3b `agreement-preview`** -- mapper + `GET /preview` + frontend Preview panel.
- **CR-3c `agreement-generate-draft`** -- `POST /document` stores as draft (locked after signing) +
  frontend "use this document".

### manual-test bug found + fixed (real-app run)
- During the user's manual test the app returned **500 on Create Agreement**. Diagnosis: the backend
  was **down** -- my `application.yml` edit had appended the `gotenberg:` block **between**
  `storage.bucket` and `storage.access-key`/`secret-key`, so those two keys were re-indented under
  `gotenberg:` and MinIO started with a null AccessKey -> `minioClient` bean failed -> app never
  came up -> Vite dev-proxy surfaced the dead backend as a 500. The full test suite had stayed
  green because the Testcontainers harness overrides the `minioClient` bean (`@ConditionalOnMissingBean`),
  masking the broken YAML -- a case only a real bootRun catches.
- Fix: moved `access-key`/`secret-key` back under `storage:`. Restarted `start_local.sh`
  (health 200 in ~16s); reproduced the exact create payload -> **HTTP 201** (agreement + both
  parties + durationMonths 11). Lesson logged: config edits need a real bootRun, not just tests.
