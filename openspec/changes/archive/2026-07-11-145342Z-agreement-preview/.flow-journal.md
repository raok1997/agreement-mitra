# Flow journal -- agreement-preview (CR-3b)

Second of three increments. Maps a captured `Agreement` onto the CR-3a render engine and previews
the filled document inline from the capture screen; upgrades the bundled template to a complete
India-standard rental agreement (user request during CR-3a manual test).

## Stage log

### propose (in progress)
- Wrote proposal.md, design.md, tasks.md, and two spec deltas:
  - NEW `agreement-preview`: `GET /{id}/preview` inline PDF (no-store, not stored, 404 unknown) +
    no-PII-in-logs.
  - MODIFIED `document-rendering`: the bundled template becomes a complete India-standard rental
    agreement (content change only; render contract unchanged).
- Scope decision: no new captured agreement fields -- standard clauses are boilerplate filled from
  existing data (parties, property, rent/deposit, dates, duration) + the agreement date.
- Mapper lives in `signing.agreement` (reads the aggregate's package-private accessors); a read-only
  `AgreementDocumentService` calls the `documents` public `DocumentRenderer` -- signing depends only
  on that interface (ModularityTests stays green).
- Frontend: `fetchAgreementPreview` in client.ts returns an object URL; CaptureForm embeds it.

### review (done)
- User directed "implement CR-3b" and added the India-standard-template ask. For a template, the
  meaningful review is the rendered output -> proceed through apply and show it at the manual gate.

### apply (done)

### manual-test template change (witnesses removed)
- User asked whether a digital agreement needs a witness. Answer: no -- a rental/leave-and-licence
  agreement needs no witness attestation (attestation is for mortgage/gift/will), and with Aadhaar
  eSign the audit trail serves the evidentiary role; witnesses aren't in the eSign signer set, so
  the witness lines would render blank/unfillable. User chose **remove**.
- Removed the Witnesses block (and its CSS) from `rental-agreement.html`; added a one-line note that
  the agreement is executed via Aadhaar eSign, no attesting witness required. Updated the
  `document-rendering` spec delta, design D-B4, and task 3.1 accordingly (no test change -- the
  render assertion never depended on witnesses). Re-ran preview + template tests: green.
- Re-rendered the user's agreement via the live endpoint (39.7 KB inline no-store PDF) for eyeball.

### manual-test (signed off)
- User reviewed the India-standard preview (via the live `/preview` endpoint and the in-app Preview

  rental agreement). Approved archiving CR-3b and proceeding to CR-3c.
