# Flow journal -- agreement-generate-draft (CR-3c)

Third and final increment of the CR-3 arc. Wires the CR-3b render together with the existing
draft-upload path so the rendered document becomes the agreement's signable draft: capture ->
preview -> generate -> stamp -> eSign, no manual upload.

## Stage log

### propose (in progress)
- Wrote proposal.md, design.md, tasks.md, and the `draft-ingestion` MODIFIED spec delta
  (system-generated draft; overwrite-until-signing then locked; 404/400).
- Key decision (D-C1): the controller orchestrates two existing, independently-transactional
  collaborators -- `AgreementDocumentService.renderPreview` (CR-3b) then `DraftService.attachDraft`
  -- rather than a combined `@Transactional` service method (which would self-invoke the read-only
  render and hold a DB tx across the Gotenberg HTTP call).
- The freeze rule (409 once a signing request exists) is **inherited** from `attachDraft`, not
  re-implemented -- generated and uploaded drafts behave identically.

### review (done)
- User approved building CR-3c after CR-3b archive ("Archive CR-3b and build CR-3c").

### apply (done)

  persistence, mapping, or schema.
- Frontend: `generateAgreementDocument` in client.ts; CaptureForm "Use this document" button + a
  saved/ready confirmation and a 409 error surface.
