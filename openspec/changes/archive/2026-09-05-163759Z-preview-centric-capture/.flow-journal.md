# Flow journal -- preview-centric-capture

Reimagines capture as document-first: the rendered agreement is the centrepiece and each data area is
an edit control around it. Absorbs the parked CR-3d (custom conditions become a section). UX layer
for the `documents` module; the capability layer is the `document-templating-platform` exploration.

## Stage log

### propose (in progress)
- Wrote proposal.md (with the full section catalog A-H + Phase 1 scope), design.md (architecture:
  live-HTML-preview-same-template, stateless partial preview, section registry, responsive shell,
  sandboxed-iframe security), and Phase-1 spec deltas + tasks (+ a future-phase backlog).
- Key decisions: (D1) live preview = assembled HTML from the SAME template (instant, no divergence),
  PDF for download/final; (D2) stateless `POST /api/agreements/preview` from an in-progress client
  working set -- no premature persistence; (D3) renderer/template tolerate partial data with
  placeholders; (D4) pluggable section registry so the section catalog is additive; (D5) responsive
  (desktop two-pane / mobile guided + toggle) for a mobile-first market; (D6) escaped data in a
  sandboxed iframe -- markup/data boundary preserved.
- Scoping insight: Phase 1 needs NO schema change (preview is client-driven; only final save persists,
  via existing create + generate). New-section persistence is Phase 2+ via an attributes store.
